# TASK-08-15 — Backend: Flag `force_pwd_change` en Login Response

**Sprint**: S08-PAYMENTS-ACCOUNTING
**Label**: TECH/DOMAIN
**Status**: TODO
**Dependencia**: TASK-08-14 debe estar COMPLETED antes de ejecutar esta tarea.
**Modo**: 🟡 Zona Ámbar — requiere validación del PO antes de proceder

---

## Objetivo
Extender la respuesta del endpoint de login (`POST /auth/login`) para que, cuando el usuario tenga un flag activo en `system_configs`, incluya `"require_password_change": true` en el JSON devuelto.

---

## Restricciones Críticas (VISION.md)
> ⚠️ CAUTION
> - **NO** añadir columnas a las tablas existentes de la base de datos.
> - Esta tarea **sí** requiere modificar `AuthService.login()` y/o `AuthController.login()` de forma mínima y quirúrgica (solo agregar la consulta al `system_configs` y el campo en el retorno).
> - El campo `require_password_change` es solo informativo en la respuesta; **no debe bloquear** la autenticación en sí misma.
> - **NO** usar SMTP ni envío de correos.

---

## Archivos a Modificar (Solo los indicados)

### `backend/src/auth/auth.service.ts`
En el método `login()`, después de validar las credenciales y antes del `return`:
1. Consultar `SystemConfigRepository.findOne({ where: { key: \`force_pwd_change:\${user.id}\` } })`.
2. Si existe y su `value === 'true'`, añadir `require_password_change: true` al objeto de respuesta.
3. Si no existe, el campo se omite (no incluir `false` explícito para evitar ruido en el token).

> ⚠️ IMPORTANTE: Inyectar `SystemConfigRepository` en `AuthService` vía `@InjectRepository(SystemConfig)`.
> El constructor de `AuthService` ya recibe dependencias — solo añadir la inyección al constructor, no refactorizar ni mover código.

### `backend/src/auth/auth.module.ts`
Añadir `SystemConfig` al `TypeOrmModule.forFeature([...])` de este módulo si no está ya registrado.

---

## Respuesta Esperada del Login (cuando el flag está activo)
```json
{
  "access_token": "eyJhb...",
  "user": {
    "id": "abc-123",
    "email": "usuario@email.com",
    "role": "client"
  },
  "require_password_change": true
}
```

---

## Validación
- [ ] `npm run build` debe completar sin errores en `backend/`.
- [ ] Login normal (sin flag) → respuesta sin el campo `require_password_change` → OK.
- [ ] Login de usuario con flag activo → respuesta contiene `"require_password_change": true` → OK.
- [ ] El flag NO debe impedir el acceso; el token debe ser válido y funcional.

---

## Turno Adversarial (Pre-Código)
**Riesgo**: Inyectar `SystemConfigRepository` en `AuthService` puede generar un conflicto de dependencias circulares si `SystemConfig` está en un módulo separado no importado por `AuthModule`.
**Mitigación**: Verificar `app.module.ts` para confirmar que `SystemConfigModule` ya está importado globalmente, o registrar `SystemConfig` directamente en `AuthModule.imports`.
