## Objetivo
Detectar la bandera `require_password_change: true` en la respuesta del login e interceptar la navegación del usuario, mostrando una pantalla/modal de cambio de contraseña **obligatorio** antes de otorgar acceso a cualquier página del sistema.

---

## Restricciones Críticas (VISION.md)
> ⚠️ CAUTION
> - **NO** modificar páginas o componentes de UI existentes (no editar `page.tsx` de admin, catalog, etc.).
> - La intercepción debe implementarse como un componente nuevo que se inyecta de forma pasiva.
> - **NO** usar SMTP.

---

## Archivos a Crear (Nuevos)

### `frontend/components/auth/ForcePasswordChangeModal.tsx`
Componente modal de pantalla completa (overlay) que:
- **Solo se renderiza** cuando `require_password_change === true` en el contexto de autenticación.
- Muestra:
  - Título: "Debes cambiar tu contraseña para continuar"
  - Campo: "Contraseña actual" (type password)
  - Campo: "Nueva contraseña" (type password, mínimo 8 caracteres)
  - Campo: "Confirmar nueva contraseña"
  - Botón: "Actualizar Contraseña"
- Al enviar, llama a `PATCH /admin-actions/me/change-password` con las credenciales.
- Si respuesta es 200 OK:
  - Eliminar el flag del contexto de autenticación.
  - Cerrar el modal y permitir navegación normal.
- Si error → mostrar mensaje de error dentro del modal (no navegar fuera).
- **No incluir opción de "saltar" ni cerrar el modal sin completar el cambio**.

### Diseño Visual
- Usar la misma paleta y tipografía del sistema existente.
- Fondo oscuro semitransparente (overlay `bg-black/60`).
- Tarjeta central con bordes redondeados, padding generoso.
- Input fields con los mismos estilos que el formulario de login existente.

---

## Integración Pasiva

### Modificar `frontend/context/AuthContext.tsx` (o equivalente)
Localizar el archivo de contexto de autenticación. En la lógica de `login()`:
1. Después de guardar el token, verificar si `response.require_password_change === true`.
2. Si es true, guardar `requirePasswordChange: true` en el estado del contexto.

### Modificar `frontend/components/layout/ClientLayout.tsx` o equivalente
En el layout raíz donde todos los usuarios autenticados pasan:
1. Leer `requirePasswordChange` del contexto.
2. Si es true, renderizar `<ForcePasswordChangeModal />` encima de todo el contenido (portal o conditional render).

> ⚠️ INVESTIGAR PRIMERO: Localizar el archivo real de AuthContext y el layout raíz antes de editar. No asumir rutas.
> Archivos a buscar:
> - `frontend/context/` o `frontend/app/context/`
> - `frontend/components/layout/`

## Validación
- [ ] Login de usuario normal (sin flag) → acceso directo sin modal → OK.
- [ ] Login de usuario con flag activo → modal de cambio de contraseña aparece → no se puede navegar → OK.
- [ ] Completar el cambio → modal desaparece → acceso normal al sistema → OK.
- [ ] Contraseña incorrecta en el modal → error visible → no navega → OK.
- [ ] Diseño responsive en mobile (375px) y desktop (1280px).
