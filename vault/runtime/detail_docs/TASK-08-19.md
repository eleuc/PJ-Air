## Turno Adversarial (Pre-Código)
**Riesgo 1**: El test 3.4 restablece la contraseña de `rubendarioc` a `Sebas1007.` al final. Si el test falla a mitad de camino, la cuenta quedará con `ResetRuben2026!` como contraseña activa.
**Mitigación**: El spec incluye un paso de limpieza `afterAll` que restaura la contraseña original de `rubendarioc` directamente vía API (`PATCH /admin-actions/users/:id/reset-password` + `PATCH /admin-actions/me/change-password`) o vía script local.

**Riesgo 2**: El usuario desechable `pwd-test@jhpanesbakery.com` puede quedar huérfano si la suite falla antes del `afterAll`.
**Mitigación**: Ejecutar `backend/scripts/cleanup-test-users.js` ante cualquier fallo catastrófico.

**Riesgo 3**: `eleuterioc@gmail.com` podría no estar disponible en el entorno local de pruebas.
**Mitigación**: Siempre usar `admin@test.com` / `123123` como fallback de admin. Ambas credenciales están documentadas en las constantes del spec.
